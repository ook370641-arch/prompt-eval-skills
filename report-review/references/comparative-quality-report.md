# 对比 / 对照类报告标准

当报告要做任何形式的**对比 / 对照**时读取本 reference，包括但不限于：

- 新旧版本、模型、prompt、渲染链路、解析本、讲解稿、总结、UI 文案等**内容质量对比**；
- **前后对照**（同一对象施加某处理前后，如补 ASR 前/后、加字段前/后）；
- **消融对照**（去掉某模块/规则的版本 vs 完整版本）；
- **变量注入实验**（逐样本注入某种内容——ASR、检索片段、外部知识、新特征——再比较）。

本 reference 关注的不是"谁写得更好"这一种对比，而是**一切"改了一个变量看效果"的对照实验**。

## 核心问题

报告必须回答：

> 在对照成立（变量真被隔离、且真被施加）的前提下，新版本/处理是否在正确维度上足够好、风险可接受，因此可以替代旧版、灰度或继续验证？

平均分、表面 Δ 都不能单独支撑结论——**必须先证明对照本身成立**。

## 对比变量构造核查（对照成立的前提，先查这一节）

对照实验的第一性问题不是"结果差多少"，而是"**变量到底有没有被真正、均匀地施加**"。当对比变量是**逐样本注入的内容**（ASR 文本、检索片段、外部知识、新字段、新特征等），它在样本间往往注入得不均匀——有的样本真注入了，有的注入为空或失效。失效样本混进对照组，会直接污染 Δ，让"没变化"被误读成"处理无效"，或让重跑噪声被误读成"处理有效"。

必须检查：

1. **注入分布**：列出该变量在各样本上的实际取值分布——多少条真注入了、多少条注入为空/失效、长度或质量分布如何。不能只说"给所有样本加了 X"。
2. **失效样本剔除**：注入为空/失效的样本（如转写为空的 ASR）**不能计入"已施加处理"的处理组**。它们补前补后输入字节相同，等于安慰剂，必须单独标出并在解读 Δ 时排除。
3. **翻转拆解**：差异不能只给净 Δ（如 ±4.3pp），必须拆成"**变好几条、变差几条、净几条**"，并为每条翻转标注其对应的变量取值（空/短/长、质量好坏）。这样才能看出方向是真实的还是被失效样本制造的。
4. **变量取值与结果挂钩**：变好/变差的样本，其变量取值是否呈现系统性规律（如"变好的全是空注入""变差的全是长注入"）。若变好样本恰好都是失效注入，则该方向的"改善"不成立。

注入分布速查表（按需填写）：

| 注入类别 | 条数 | 代表样本 | 该类是否计入处理组 | 在结果中的角色 |
| --- | --- | --- | --- | --- |
| 真注入（非空、有效） | | | 是 | 处理组主体 |
| 注入为空 / 失效 | | | 否 | 安慰剂，须剔除出 Δ 解读 |
| 注入异常（脏 / 错字 / 超长） | | | 是，但单独标注 | 可能是负向来源 |

硬规则：

> 在解读任何对照 Δ 之前，必须先证明"处理组里的样本确实都被施加了处理"。若存在失效注入样本，必须把它们从处理组剔除后重算方向，否则 Δ 不可信。

## 必备证据

1. **质量维度**
   - 明确定义本任务中的“质量”是什么。
   - 例如：正确性、完整性、结构性、有用性、可读性、一致性、展示质量、用户适配度。

2. **主决策指标**
   - winner 数、通过率、人工偏好、绝对质量阈值或加权分。
   - 说明该指标为什么能回答主决策。

3. **分布信息**
   - 均分。
   - winner 数。
   - 持平数。
   - 极端低分 case。
   - 回归 case。

4. **评测工具可靠性**
   - 如果使用 LLM-as-judge，必须说明是否经过人工校准。
   - 如果没有人工校准，结论只能支持观察或灰度建议。

5. **分桶分析**
   - 新版在哪些场景胜出？
   - 旧版在哪些场景胜出？
   - 哪些用户可见失败最重要？

6. **决策边界**
   - 全量替代、灰度、局部使用、继续验证或拒绝。

## 常见问题

| 问题 | 判断信号 | 纠偏方向 |
| --- | --- | --- |
| 变量注入未核查 | 只说"给所有样本加了 X"，未给注入分布；空/失效样本混入处理组 | 补注入分布表，剔除失效样本后重算 Δ |
| 只看净 Δ 不拆条数 | 只报 ±4.3pp，看不出变好变差各几条 | 拆成变好/变差/净条数，每条标注变量取值 |
| 失效注入冒充改善 | "变好"的样本恰好都是空/失效注入 | 判定该方向改善不成立，归因为重跑噪声 |
| 均分越级 | 新版均分更高，所以说新版全面更好 | 补 winner 数、回归 case 和低分 case |
| 忽略评测偏差 | LLM judge 未校准就作为最终判断 | 补人工盲评或降级结论 |
| 质量维度混淆 | 结构变好，但正确性变差 | 拆分维度并回到产品优先级 |
| 极端失败被隐藏 | 平均表现好，但存在严重坏例 | 补低分和回归 case 复核 |
| 替代结论过强 | 证据只支持灰度，却写成全量替换 | 让决策强度匹配证据强度 |

## 推荐结构

1. 对比问题与决策目标。
2. 对比版本与样本口径。
3. 对比变量构造核查：变量注入分布、失效样本剔除。
4. 质量维度与评分 rubric。
5. 评测工具可靠性 / 校准情况。
6. 主结果：winner 数或主决策指标；翻转拆成变好/变差/净条数。
7. 分数分布与分桶分析。
8. 回归 case 和极端失败 case。
9. 解释边界。
10. 决策：替代 / 灰度 / 局部使用 / 继续验证。

## 示例

通用规则：

> 新版本均分更高，并不一定适合全量替代。若它在更多 head-to-head case 中失败、存在严重回归，或评测器未经人工校准，就只能支持灰度观察或继续验证。

历史示例：

在对比新旧两个生成内容版本时，新版部分维度均分更高，但旧版 head-to-head 胜出更多。这类证据可以支持灰度观察，不能自动支持全量替代。
