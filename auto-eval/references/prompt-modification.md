# 提示词精修框架:Reflector→Refiner(防回归)

> 核心痛点:数据分析得出一条结论后,最自然的动作是**把结论原文焊进提示词**——分析说"X 类 case 仍可判高",就加一条"X 即判高"。这几乎必然过拟合:这条窄规则治好了眼前几条,却把原本判对的同型 case 带偏,**回归率暴增**。文献叫它 **prompt distributional overfitting / rule narrowing(规则窄化)/ rule dilution(规则稀释)**。本框架是这条链的防回归骨架。

## 两个角色:先定效果,再落措辞

整条精修拆成两个角色,**绝不合并**——合并就是"边想边写",窄规则就是这么混进去的。

### Reflector(诊断 + 定效果)——回答"我希望提示词达成什么效果"

- 输入:Part1 的根因(带 COT 证据 + 带符号混淆矩阵)。
- 产出:一条**与措辞无关的效果描述**(spec),例:"让模型对'纯资讯罗列、无背景解释'的 case 不再判高"——**不是**"加一句『资讯罗列即判中』"。
- 关键:Reflector 的产出是**意图**,可被人工在闸门一审核(审的是"这个效果该不该追求",不是"这句话写得好不好")。

### Refiner(落措辞)——回答"这条规则到底怎么写"

- 输入:被批准的效果描述。
- 产出:提示词里的实际措辞。
- **铁律:禁止把数据分析的 case 内容、GT 标签、单条 case 特征原文照搬进 prompt**。Refiner 写的是**可复用原则**,不是 case 备忘录。

> 为什么拆两段:GradeOpt 的 Refiner 会把 case 示例原文嵌进规则——这恰恰是过拟合源头。我们**采用它的两角色结构,但在这一点上反向**:只写原则,永不嵌 case。DSPy 的 signature 思想同义:人定契约(intent),措辞(realization)是另一层,别混。

## 加 / 删 / 改:每条策略先分流

**这是框架的核心。** 每条策略动手前,先判它属于哪一型——决定该加内容、删内容、还是改内容。错型会直接制造回归。

| 类型 | 病象 | 正确动作 | 为什么 | 回归风险 |
|---|---|---|---|---|
| **遗漏型** | 某类 case 提示词根本没覆盖,模型无依据 | **ADD 一条原则**(case-agnostic,描述类别不描述个例) | 真空地带需要填,但填的是原则不是补丁 | 低——只要写成原则、不写成"X即判Y" |
| **过具体补丁型** | 已有一条"X即判Y"窄规则在误伤(你这次的主病) | **REMOVE 或上抽**:删掉窄规则,或抽象成更高层原则 | 窄规则的作用域太小,治个例伤同型;删掉/上抽才是解 | 删错会反弹,删前必做返回率预判 |
| **过严 / 过宽型** | 一条骨架约束触发条件太松/太紧 | **EDIT 收窄 / 放宽触发条件,绝不删整条骨架** | 删骨架=用更大错误覆盖小错误(项目血泪:删"简单≠高"→无脑判高) | 中——改触发条件可能连带影响邻型,做预判 |
| **耦合型** | 单 prompt 内多类约束相互放大(如判高/判不适用/判中耦合) | **物理隔离 / 分阶段双判**(先判 A 类,再对剩余 judge B/C) | 同一段里改任一处,下压力被放大;隔离才切断传导 | 高——这是项目"四维度同改必崩"的根;隔离本身要单独验 |

**分流口诀**:遗漏→加原则;补丁误伤→删/上抽;骨架过严宽→改触发条件;耦合→隔离。**先问"是加还是删",别默认加**——你的主病就是"什么都往里加"。

## CASE_PATCH 拒收:一条规则配不配进 prompt

Refiner 落每条规则前,过这道自检(TextReg 的 `CASE_PATCH` vs `GENERALIZED_RULE` 判别):

- **它描述的是一个类别,还是一条 case?** 出现具体片名/具体 nid 特征/GT 原文 → CASE_PATCH,拒收,回去抽成原则。
- **它跨几条 case 复现?** 只从 1 条 badcase 来 → 复现支撑不足,先存疑不写进 prompt(ProTeGi:一条梯度要跨多个 minibatch 赢)。≥3 条同型才够格成规则。
- **删它会不会让 prompt 更短且不丢覆盖?** 会 → 说明它是冗余补丁,本就不该在(MDL/Occam:规则要"自付其费",压掉的错误得大于它增的长度)。

> 把这道自检塞进闸门二:子 agent 除了核"根因↔diff 覆盖",**还要核"有没有把具体 case 写进 prompt"**——发现 CASE_PATCH 一律打回。

## GT 错:前置筛,不占主精力

> 用户明确:**判 GT 错最后再筛,别占太多精力**。它不是加/删/改决策表的并列第五型(它根本不改 prompt),而是分流**之前**的一道轻量前置问:"这是 prompt 能治的,还是 GT 本身标错了?"

- 默认**当 prompt 问题处理**;只有证据很硬时才判 GT 错并踢出拟合目标。
- 判 GT 错需要证据(Confident Learning / 标签噪声文献的纪律,**这里只取轻量版**):① 是**逆序**(低↔高)不是相邻档(中↔高);② 判官高置信;③ **第二个独立模型同向 disagree**;④ COT 引用了**可核验的客观事实**(如"音轨损坏""全程图文轮播无音频"),而非"我观点不同"。四条都中才升级为候选,最终由人盲评拍板。
- 证据不足 → 留在拟合目标里当 prompt 问题或模糊样本,**绝不靠改 prompt 去迎合可疑标注**(那是把标注噪声洗成模型偏置)。
- 真判错的,写进 CLAUDE 的「GT 排除项」(nid + 为什么不拟合),不进 prompt。
- 红线:某维度 GT 改动率 >~5–10% → 不是散落标错,是 rubric/taxonomy 系统性问题,该重标整个维度,不逐 case 打补丁。

## 一条策略走完全程的样子

```
Part1 根因(带COT)
  │
  ├─ 前置筛:是 prompt 问题还是 GT 错?  ─→ GT 错(四条硬证据+盲评)→ 进 CLAUDE 排除项,结束
  │
  ▼ (prompt 问题)
Reflector:写出与措辞无关的"效果描述"(intent)
  │
  ▼
加/删/改分流:遗漏→ADD原则 / 补丁误伤→REMOVE上抽 / 过严宽→EDIT触发条件 / 耦合→隔离
  │
  ▼
闸门一(人工):出示 根因+证据+效果描述+分流类型+返回率预判,逐条批准
  │
  ▼
Refiner:落措辞 —— 禁 case 照搬,只写可复用原则
  │
  ▼
CASE_PATCH 自检:描述类别？跨≥3 case 复现？删它会不会更短不丢覆盖？
  │
  ▼
闸门二(子 agent):根因↔diff 双向映射 + 查有没有 case 照搬进 prompt
  │
  ▼
跑测 → Part4 返回率实测 + 归因(读 COT 定位哪条规则致伤:少规则 or 多规则)
```

## 与 Part2/Part4 的挂钩

- **闸门一 = Reflector 产物的人工审核**:审"效果描述"该不该追求,顺带审分流类型对不对(别把该删的写成加)。
- **写 = Refiner**:落措辞,守"禁 case 照搬"铁律。
- **闸门二 = Refiner 没跑偏的核验** + 新增"查 case 照搬"。
- **Part4 返回率归因 = Reflector 对返回 case 再跑一遍 Step1**:读迭代版 COT,定位是哪条**新增/改动**的规则致伤,标**少规则**(漏了约束)还是**多规则**(加了窄规则),结论回写 CLAUDE「迭代教训」累加。
