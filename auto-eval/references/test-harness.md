# 跑测脚手架方法论（Part 3 的通用骨架）

> auto-eval 的 Part 3「跑测」本身不写进 skill——api / 数据格式 / 视频或文本通路每个项目都不同，写死必然把某个项目的工作流带进通用库。本 reference 沉淀的是**跨项目复用的脚手架方法论与验收口径**：一个合格的跑测脚手架该长什么样、产物该怎么组织、看板该怎么设计。具体的 api key、host、脚本路径、数据文件一律落在**项目自己的 README/CLAUDE**，不进这里、更不进公开库。

## 为什么要有脚手架，而不是每次让 agent 现攒脚本

散落脚本里 agent 每次自行选择「用哪个脚本、落哪个目录、按什么口径评分」是 A/B 迭代最大的隐性噪声源。把「推理→评测→看板」固化成一条命令，好处是：

- **口径锁定**：样本集、维度次、评分尺子、temperature 都被脚本焊死，A/B 天然同口径。
- **可断点续传**：237 条 × 多模型耗时以小时计，跑挂了要能接着跑，不重烧已成功的 case。
- **验收可查**：产物在不在、条数够不够、看板生成没有——从「看文档写得好不好」变成「看产物对不对得上」。

## 三段式结构：run_inference → run_eval → gen_dashboard

一条龙入口 `run_all` 串起三步，三步的 `--models` / `--suffix` 必须一致：

| 阶段 | 职责 | 关键纪律 |
|---|---|---|
| **run_inference** | 对每条 case 跑模型推理，落原始输出 jsonl | 断点续传；failed 默认重跑；**temperature=0**（消除同 prompt 重跑抖动，见下）；模型 id 落进产物 jsonl |
| **run_eval** | 按评分尺子对推理结果打分，落评测 jsonl | 严格校验维度次完整性（少一条即报错，不静默）；每条只评该 nid 有 GT 的维度 |
| **gen_dashboard** | 生成 xlsx/html 看板 + 空白样板 | 一行一 case；不一致标红；metadata sheet 溯源 |

**默认严格验收**：每个 requested model 必须全样本推理成功、全维度次评测完整、看板生成成功。调试才显式加 `--allow-partial`。

## temperature=0 是 A/B 的前提

LLM 推理 temperature≠0 时本身有重跑随机性，这是 A/B 最致命的隐藏混杂变量——小样本下一条 case 的「翻转」可能根本不是提示词改动引起，而是抖动。**脚手架把 temperature 焊死为 0**，从源头消除；对结论关键的少数 case，仍建议同输入重跑 3 次取众数再纳入对照。

## 评分尺子：分级 + 带符号，不只是「对/错」

评测的心脏是**判分函数**，它决定了一致率怎么算、混淆矩阵长什么样。分级评测（有序档位任务，如 高/中/低）的正确尺子**不是二元对错**，而是**按档位距离分级 + 带方向符号**——这两点直接喂 Part1 的带符号混淆矩阵。

以 `RANK = {高:3, 中:2, 低:1}` 为例的判分规则：

| 情形 | 分数 | 说明 |
|---|---|---|
| GT == Pred（同档） | **2** | 完全一致 |
| 差一档（如 高↔中、中↔低） | **1** | 相邻档错误，不算逆序 |
| 差两档（高↔低） | **0** | **逆序**，最严重 |
| 「不适用」判成任意档 / 反之 | **0** | 不适用误判，等同逆序 |
| 档位值缺失/非法 | **0** | 异常，标出来别静默 |

**关键：每条错判必须同时记「方向 + 严重度」**，而不仅是分数——
- **方向**：`GT档 − Pred档 > 0` = 模型**偏低**（判保守了），`< 0` = **偏高**（判宽松了）。
- **严重度**：差一档 = 跨一档，差两档 = 逆序。

判分函数应返回 `(分数, "GT→Pred(偏低/偏高, 跨一档/逆序)")` 这样的带符号标签，Part1 才能把整批错判聚成「系统性偏高 N 条 / 逆序 M 条」的病象，而不是只有一个干巴巴的一致率数字。

> 为什么带符号是刚需：一致率 70% 掩盖了「是偏高错的还是偏低错的、是相邻档还是逆序」。提示词是纠偏器——不知道往哪偏，就不知道该收紧还是放松。

## 模型输出解析：混合输出的鲁棒抽取

模型原始输出常是「COT + 结构化结果」混在一起（如 `<think>...</think>` 后跟 `<json_output>{...}</json_output>`，或 ```json 围栏，或裸 JSON）。评测和看板都要从里面稳定抽出 **结构化字段（level/tags/reason）+ COT**，解析必须容错、层层兜底：

**抽结构化 JSON** 的降级链（前一个失败就退到下一个）：
1. 优先匹配显式标签 `<json_output>...</json_output>`；
2. 回退 ```json ... ``` 代码围栏；
3. 再回退裸 `{...}`（兼容不同模型的外壳差异）；
4. 全失败返回 None，**当作解析失败标红**，不静默丢。

**抽 COT**：取结构化块之前的自然语言推理段（`<think>` 内容或 json 前的正文），**不主动截断**（Excel 单元格自身有上限另说）。

**非法 JSON 兜底**：结构化块本身 JSON 解析失败时，用正则提取所有 `"字段":"值"` 对拼出可用信息，提不到再返回原文——**脏输出也要尽量榨出信息，而不是整条判空**。

**看板 detail 列永不留空**：一条 case 的展示优先级 COT → reason → 结构化输出兜底，保证扫表时每行都有可读的判定依据。

## 产物组织：版本目录 + 模型分文件

产物按「版本 / 模型」两级组织，落项目 README 约定的运行目录（示例，各项目自定）：

```text
运行与评测/{版本}/
├── 推理结果_{版本}_{模型}.jsonl
├── 评测结果_{版本}_{模型}.jsonl
├── 看板_{版本}.xlsx
└── 看板样板_{版本}.xlsx
```

- **版本永不覆盖**：每版新目录，A/B 可回溯。
- **模型分文件**：pro / mini / 竞品各一套，多模型必须分别归因（同 prompt 在不同模型上偏置方向可能相反）。
- **视频/大输入不打包**：体量大的原始输入（视频等）首次跑时下载到本地缓存目录，不进产物、不进库。

## 数据资产：精简推理输入 + GT 分离

跑测需要两类数据，都由**项目自备**、不进公开库：

1. **精简推理输入**（每行一条）：`nid / 输入URL或文本 / title / 其他必要字段`。原始大文件里推理只需要这几个字段，抽薄即可。
2. **GT 标注**：只标 level（或目标指标），评测只比较 level。每条 case 只有被分配维度的 GT——**全集不是「样本数 × 维度数」全标注**，而是各维度各自的样本子集之和（如 237 条 nid 实际是 84+95+58+58 = 295 维度次）。

## 看板设计：先分清对接方

**两类表目标不同，不要混用**：

- **内部表**（迭代复盘，给自己看）：可含基线对照列、Δ、矫正/回退标记（↑改善/↓退化上色）、tags/COT 分层、metadata 溯源。服务版本 A/B 归因。
- **业务表**（交付结论，给业务方看）：只呈现「评了什么 / GT / 模型怎么答 / 为什么 / 对不对」，砍掉一切版本迭代语言（无基线对照、无 Δ、无 metadata、零本地命名）。

### 两类都遵守的通用条
- 一行 = 一个 nid。
- **输入URL 紧贴标题右侧**（扫表时点开对着标题看），不甩到最后一列。
- 得分用颜色：红=逆序/误判、黄=相邻档错、蓝=一致。
- 模型列只按本次实际 requested 且评测成功的模型建，没跑的不留空格子。
- **模型名从推理产物 jsonl 读真实 model id**，读不到就问用户，**绝不用文件夹名/文件名/内部代号兜底**——从源头把 model id 落进 jsonl。
- **列按数据自适应**：`level` 恒建列；`tags` / `reason` 整维有值才建列、全空不建，各占一列不合并。模型每维度的 `level/tags/reason/COT` 全部落进看板，不遗漏。

## 一份合格脚手架的自检

- [ ] 一条命令能跑完推理→评测→看板？
- [ ] temperature 焊死为 0？
- [ ] 断点续传：跑挂能接着跑、不重烧成功 case？
- [ ] 判分函数是**分级 + 带符号**（同档2/相邻档1/逆序0/不适用误判0），每条错判记了方向(偏高/偏低)+严重度(跨一档/逆序)，能喂混淆矩阵？
- [ ] 模型输出解析容错：结构化抽取层层兜底(标签→围栏→裸JSON)、非法 JSON 有正则兜底、解析失败标红不静默？
- [ ] 评测严格校验维度次完整性，少一条即报错、不静默？
- [ ] 产物按「版本/模型」两级组织、版本永不覆盖？
- [ ] 看板分清了内部表 / 业务表，model id 从 jsonl 真实读取，detail 列 COT→reason→兜底不留空？
- [ ] api key / host / proxy / 本机绝对路径**全部从环境变量或 CLI 参数读**，脚本里零硬编码、零密钥？
- [ ] 数据资产（推理输入、GT、视频缓存）留在项目本地，不进版本库？
